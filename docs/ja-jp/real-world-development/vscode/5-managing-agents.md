GitHub Copilot をエージェント モードで使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行します。作業は開発者のコンピューター上でリアルタイムに行われます。VS Code の Copilot Chat では、ツールの呼び出しとファイル編集の様子を確認できます。各 diff をインラインでレビューし、個別の変更を承認または拒否して、追加プロンプトで会話を方向付けながら、エディターを離れずに作業を改善または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- 作業中のセッションにライト モードの切り替え機能を追加するよう依頼します。

## シナリオ

[演習 4][previous-lesson]で使用したアクセシビリティ カスタムエージェントが、ハイ コントラスト モードを実装しています。作業中に、デザイン チームから追加の要望がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードも切り替えられるようにします。新しい会話を最初から始める代わりに、既存のセッションに追加の作業を依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は diff と **Keep** / **Undo** のコントロール付きで、Chat にインライン表示されます。

1. 演習 4 から Copilot Chat ビューに戻ります。
2. エージェントの作業中に Chat をスクロールし、ツール呼び出しを確認します。ファイルの読み取り、編集、実行を求められたターミナル コマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、diff がインラインで表示されます。
   - **Keep** を選択して変更を承認します。
   - **Undo** を選択して変更を元に戻し、エージェントに再度取り組ませます。
4. Chat 上部にある **Files changed** を開くと、このセッションでエージェントが変更した作業セット全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツールの許可を求められると、エージェントは一時停止し **Allow** を表示します。自分が許可できるコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を完了するまで待ちます。完了すると、変更内容の概要が表示されます。

## エージェントにライト モードを追加するよう依頼する

ハイ コントラスト モードが実装されたので、同じ会話にライト モードの切り替え機能を追加します。同じ Chat セッションを続けることで、エージェントは以前の作業のコンテキスト（変更したコンポーネント、スタイルの方針、設定した local storage のパターンなど）を維持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは以前の変更を確認し、ライト モードの追加を提案します。
3. ハイ コントラスト モードと同様に、追加された編集をレビューします。それぞれの diff で **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合（たとえば、気に入らない方法でトグルのユーザー インターフェイス (UI) をリファクタリングする場合）は、Chat 入力欄の横にある **Stop** ボタンで停止し、説明を補う追加メッセージを送ります。

> [!TIP]
> 進行中のセッションを方向付ける方が、最初からやり直すよりも速く済みます。追加プロンプトで調整（「Cascading Style Sheets (CSS) を簡潔にして、セレクターを重複させず CSS 変数を使用する」）、軌道修正（「トグルを3つにせず、既存のユーザー インターフェイス (UI) の設定パネルにライト モードを追加する」）、範囲の拡張（「両方のトグルにキーボード ショートカットも追加する」）を依頼できます。

## 変更された作業セットをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開いて diff を確認します。カスタムエージェントのアクセシビリティ パターン（Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HyperText Markup Language (HTML)、local storage による設定の保持）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使い、作業中のセッションを監視して方向付けました。ファイル編集が行われるたびにレビューし、変更を承認または拒否し、コンテキストを失わずに追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個別のファイル編集を承認または拒否しました。
- 追加プロンプトを使って、進行中のセッションを方向付けました。

次の[レッスン][next-lesson]では、アクセシビリティ作業を pull request として公開し、このラボでローカル カスタムエージェントが生成した変更をレビューします。
